## Clean Architecture — Feature Structure

Every feature in `local_delivery_customer/lib/features/` follows this exact layout:

```
features/
└── feature_name/
    ├── domain/
    │   ├── models/         # Pure Dart domain models (Equatable, no Firebase imports)
    │   ├── repositories/   # Abstract repository interfaces
    │   └── use_cases/      # One class per use case; method must have a descriptive name (NOT call())
    ├── data/
    │   ├── dto/            # Firebase DTOs: fromFirestore() + toDomain() (Firestore-specific parsing here)
    │   ├── sources/
    │   │   ├── x_remote_source.dart          # Abstract interface (no Firebase imports)
    │   │   └── firebase/
    │   │       └── firebase_x_source.dart    # Firebase implementation; throws exceptions on error
    │   └── repositories/   # XRepositoryImpl: takes XRemoteSource via constructor; returns Either<Failure, T>
    ├── cubit/
    │   ├── feature_cubit.dart   # Business logic, calls use cases; uses UserSession for identity
    │   └── feature_state.dart   # Immutable state classes (Equatable)
    ├── presentation/
    │   ├── pages/          # One page per screen (BlocProvider + BlocConsumer/Builder)
    │   └── widgets/        # Small, single-purpose sub-widgets extracted from pages
    └── router/
        └── feature_page_route.dart  # Implements LDPageRoute, defines GoRoute
```

**The auth feature is the canonical reference** — it is the most complete and correctly implements every layer.

### Key Architecture Rules

- **Domain models** must never import Firebase or Firestore — pure Dart only.
- **DTOs** live in `data/dto/` and handle all Firestore-specific types (e.g. `Timestamp` → `DateTime`, inject `doc.id`). Each DTO has `fromFirestore()` and `toDomain()`.
- **Remote source interfaces** (`x_remote_source.dart`) have no Firebase imports — they define the contract only.
- **Firebase sources** throw exceptions on error; they never return `Either`.
- **Repository impls** catch exceptions from sources and wrap results in `Either<Failure, T>`. They also convert DTOs to domain models via `dto.toDomain()`.
- **Cubits** must never import Firebase directly. Use `UserSession.instance` for user identity (userId, isLoggedIn), and use cases for all data operations.
- **Use case methods** must have descriptive names — never `call()`. Examples: `getStores()`, `placeOrder()`, `sendOtp()`.

## Dependency Injection

GetIt is used. The locator is initialized in `main.dart` via `setupLocator()` which calls four files in order:

1. `di/data_source_locator.dart` — all remote sources as `registerLazySingleton` (interface → Firebase impl)
2. `di/repository_locator.dart` — all repos as `registerLazySingleton`; each repo receives its source via `locator<XRemoteSource>()`
3. `di/use_case_locator.dart` — all use cases as `registerLazySingleton`
4. `di/cubit_locator.dart` — **CartCubit as singleton** (persists across pages), all others as `registerFactory` (fresh per page)

To add a new feature: register its source in `data_source_locator.dart`, repo in `repository_locator.dart`, use case in `use_case_locator.dart`, cubit in `cubit_locator.dart`, and route in `ld_app_router.dart`.

## Routing

Routes are defined in `lib/app/router/`:

- `ld_app_routes.dart` — `LDAppRoute` enum with `.path` extension (e.g., `/store/:storeId`)
- `ld_page_route.dart` — `LDPageRoute` abstract class + two transition builders:
  - `buildPageWithSlideTransition()` — 280ms slide from right (use for most push navigations)
  - `buildPageWithNoTransition()` — instant (use for tab roots like Home, Login)
- `ld_app_router.dart` — central `GoRouter` config; auth redirect uses `UserSession.instance.isLoggedIn`

Each feature's route class implements `LDPageRoute` and provides a single `GoRoute get route`. Exception: `AddressPageRoute` returns `List<GoRoute> get routes` (covers `/addresses` and `/addresses/add`).

Navigate with GoRouter: `context.push('/path')`, `context.go('/path')`, `context.pop()`.

Pass data between screens via `extra: {'key': value}` and read it from `state.extra`.

## State Management (Cubit)

Pattern used for every cubit:

```dart
// state.dart
abstract class FeatureState extends Equatable { ... }
class FeatureInitial extends FeatureState {}
class FeatureLoading extends FeatureState {}
class FeatureLoaded extends FeatureState { /* data + copyWith */ }
class FeatureError extends FeatureState { final String message; }

// cubit.dart
class FeatureCubit extends Cubit<FeatureState> {
  FeatureCubit(this._useCase) : super(FeatureInitial());
  Future<void> load() async {
    emit(FeatureLoading());
    final result = await _useCase.getItems();   // descriptive method name, not call()
    result.fold(
      (failure) => emit(FeatureError(failure.message)),
      (data)    => emit(FeatureLoaded(data: data)),
    );
  }
}
```

Pages use `BlocProvider(create: (_) => locator<FeatureCubit>()..load(), child: ...)` and `BlocConsumer` for side effects + `BlocBuilder` for UI.

## Firebase Integration

### Service Layer

- `lib/core/utils/firebase_service.dart` — singleton wrapping `FirebaseAuth` and `FirebaseFirestore`. Access via `FirebaseService.instance`.
- `lib/core/session/user_session.dart` — singleton exposing user identity (`userId`, `phoneNumber`, `isLoggedIn`). **Cubits and the router use this — never import `FirebaseService` directly outside the data layer.**
- `lib/core/data/remote/firebase/firebase_collections.dart` — all Firestore collection name constants. Always use these; never use string literals for collection names.

### Rules

- Never call `FirebaseAuth.instance` or `FirebaseFirestore.instance` directly outside of Firebase source files.
- Always use `FirebaseService.instance` when you need Firebase inside a source implementation.
- Firestore Timestamps must be converted to `DateTime` in the DTO layer — never in domain models or cubits.

## Error Handling

All repository methods return `Either<Failure, T>` from `dartz`. Failure types are in `lib/core/utils/failure.dart`:

- `ServerFailure` — Firebase/network errors
- `AuthFailure` — Firebase `AuthException`
- `NetworkFailure`, `NotFoundFailure`, `ValidationFailure`, `CacheFailure`

Cubits call `.fold((failure) => ..., (data) => ...)` to unwrap results.

## Core Widgets

- `lib/core/widgets/app_image.dart` — `AppImage(filename)` widget. Pass the filename only (e.g. `AppImage('brand_logo.png')`); it prepends `assets/` internally. Always use this instead of `Image.asset('assets/...')` directly.

## Shared UI Package (`local_delivery_ui`)

Import with: `import 'package:local_delivery_ui/local_delivery_ui.dart';`

**Colors:** `LDColors.primary`, `LDColors.accent`, `LDColors.background` (sage), etc. — never use raw hex in app code.

**Text styles:** Use `context.titleLarge`, `context.bodyMedium`, etc. (extension on `BuildContext` from `ld_typography.dart`) rather than `Theme.of(context).textTheme.bodyMedium`.

**Key widgets:**
- `LDButton` / `LDOutlineButton` / `LDTextButton` — primary actions
- `LDTextField` — all text inputs
- `LDOtpField` — 6-box OTP input with auto-advance, paste, backspace support
- `LDNetworkImage` — cached image with loading/error states
- `LDLoadingWidget` — full-screen or inline spinner
- `LDErrorWidget` — error state with optional retry
- `LDEmptyStateWidget` — empty list state
- `LDToast.show(context, message, type)` — snackbar notifications
- `LDStatusChip` — order status badge (uses `LDOrderStatus` enum)

**Theme:** Applied in `LDTheme.light` — use `MaterialApp.router(theme: LDTheme.light)`.

## Code Style Conventions

- **Prefix:** All shared UI classes use `LD` prefix. App-specific classes have no prefix.
- **Widget decomposition:** Pages should delegate to small, single-purpose widget files in `presentation/widgets/`. Avoid long build methods in page files.
- **Imports:** Use relative imports within a package. Use package imports (`package:local_delivery_ui/...`) for the shared UI package.
- **Domain models:** Extend `Equatable` and implement `props`. No Firebase imports. Use `fromMap`/`toMap` only if needed for local storage — Firestore parsing belongs in DTOs.
- **DTOs:** Handle all Firestore-specific parsing (Timestamps, doc.id injection). Provide `fromFirestore(QueryDocumentSnapshot)` for list queries and `fromFirestoreDoc(DocumentSnapshot)` for single-doc fetches.
- **Naming:** Files use `snake_case`. Classes use `PascalCase`. Private helpers inside a file use `_PascalCase` for widgets, `_camelCase` for methods.
